# Project X 建设路线图

版本：盘点后建议稿  
日期：2026-08-26  
状态：仅规划，尚未执行

## 1. 目标

把这台 Mac mini 建设为一个长期、可审计的工作节点：Codex 负责调度，任务在明确权限内执行，每次运行都有可验证的输入、输出、日志、验收结论和人工审批点。

Project X 不应直接继承现有自动化的隐含权限。所有既有资产都先视为“候选来源”，经过审核、迁移和验收后才成为正式能力。

## 2. 建设原则

- **默认只读**：新适配器先提供发现、检查和报告能力。
- **交易隔离**：研究、账户只读、纸面交易、真实交易分成四个独立权限域。
- **单一调度控制面**：长期由 Codex 统一调度；launchd 只保留必要的底层守护功能，避免重复任务。
- **秘密不入库**：仓库只保存变量名、引用和权限说明，不保存凭据值。
- **可重放、可验收**：每个任务都有固定输入、输出目录、退出状态、超时和验收规则。
- **人工批准优先**：外部写入、发消息、更新 CRM、调用生产 API、纸面下单和真实下单逐级审批。
- **历史系统不复活**：OpenClaw 只作为离线迁移源，不成为并行控制面。

## 3. 阶段路线

### 阶段 2：控制面与安全基线

目标：先明确“谁能调度什么”，不接业务执行。

计划工作：

1. 为 Project X 定义任务清单格式：任务 ID、负责人、输入、输出、权限、超时、重试、审批、验收和回滚方式。
2. 建立能力分级：
   - L0：本地只读盘点
   - L1：本地生成文件
   - L2：外部系统只读
   - L3：外部系统受控写入
   - L4：纸面交易
   - L5：真实交易
3. 专项审计现有调度：`com.kevin.quant-ibkr.paper`、活跃的 Codex 研究自动化、两个暂停的 IBKR 自动化。
4. 制定 secrets 方案：优先使用系统钥匙串或受控凭据存储，项目只保存引用；建立轮换、撤销和最小权限清单。
5. 建立运行目录规范：只读输入、临时工作区、正式输出、审计日志、状态和隔离区。

完成标准：

- 每个现有自动化都有唯一负责人、状态和风险等级。
- 没有两个调度器负责同一任务。
- Project X 仓库中不存在秘密值。
- L4/L5 默认不可用。

### 阶段 3：执行与验收骨架

目标：建立不依赖具体业务的可靠任务框架。

计划工作：

1. 定义统一运行契约：任务开始/结束时间、输入摘要、产物清单、错误分类和退出码。
2. 增加 dry-run、超时、互斥锁、幂等键、重试上限和失败保留现场。
3. 建立验收器：检查文件存在、格式、时间戳、Schema、敏感信息泄露和差异摘要。
4. 建立审计日志：记录“谁请求、谁批准、做了什么、产物在哪里”，日志本身脱敏。
5. 准备离线样例数据，确保开发和测试不依赖真实生产 API。

完成标准：

- 一个纯本地样例任务可以由 Codex 调度、执行、验收并生成审计报告。
- 重复执行不会产生重复副作用。
- 失败时不会触发外部写入或后续高权限步骤。

### 阶段 4：首批低风险能力迁移

目标：用真实资产验证 Project X，但保持只读或本地输出。

优先顺序：

1. 迁移 `ibkr-readonly-status-report`，只读取本地状态或显式提供的离线快照。
2. 迁移量化项目的报告、健康检查、市场时段、风险状态和研究模块。
3. 迁移 EnergyMo 的增长工作流与 CRM 模板，先生成本地报告和待办，不写飞书。
4. 把 OpenClaw 的交易风险清单、量化决策和证券研究技能转成 Project X 文档化规则。
5. 建立资产目录页面，标记来源、版本、许可、敏感级别和权威副本。

完成标准：

- 至少三类只读任务通过固定样例和真实本地数据验收。
- 输出不包含账户凭据、认证二维码、Token 或个人敏感数据。
- OpenClaw 全程未启动。

### 阶段 5：飞书只读协作层

目标：让 Codex 能读取经授权的飞书信息并生成本地成果。

计划工作：

1. 盘点 Lark 授权范围和身份类型，不读取或复制现有秘密。
2. 先启用 Docs、Sheets/Base、Calendar、Task 的最小只读探针。
3. 定义飞书对象白名单：允许访问的文档、表格、Base、群组和知识库范围。
4. 对返回内容做脱敏、缓存期限和审计记录。
5. 将 EnergyMo/CRM 模板映射为候选数据模型，但暂不写回。

完成标准：

- 每次读取都有明确目标对象和权限证据。
- 未授权对象无法访问。
- API 失败不会触发重试风暴或切换到桌面 UI 绕过权限。

### 阶段 6：受控写入与业务闭环

目标：在人工审批下，把成果写回飞书或 CRM。

计划工作：

1. 从低风险写入开始：新建草稿文档、追加测试表行、创建未分配任务。
2. 写入前展示差异、目标对象和影响范围；写入后读回验证。
3. 建立幂等键，防止重复消息、重复任务和重复 CRM 记录。
4. 把 EnergyMo 周报、渠道漏斗和达人 CRM 作为首批候选闭环。
5. 生产对象和测试对象严格分离。

完成标准：

- 所有外部写入都可追踪到一次明确批准。
- 写入后能自动验收，失败可安全停止。
- 不存在后台静默批量修改。

### 阶段 7：量化研究与纸面交易隔离区

目标：复用量化能力，但不触碰真实资金。

计划工作：

1. 把研究、行情、账户只读和执行代码拆分为独立进程/权限。
2. 使用固定离线数据和模拟 Broker 完成回归测试。
3. 审计 `confirmed_execution.py`、Broker 适配器、启动脚本和 launchd 配置。
4. 纸面交易使用独立账户、独立凭据、硬编码环境隔离和订单上限。
5. Project X 只接收纸面交易结果和验收报告，不自动升级为真实交易。

完成标准：

- 没有真实账户凭据时，研究与测试仍能完整运行。
- 纸面订单在代码、配置、账户和网络层均无法路由到真实账户。
- launchd 与 Codex 不会重复触发同一交易任务。

### 阶段 8：长期节点运营

目标：让 Mac mini 可长期维护，而不是依赖一次性脚本。

计划工作：

1. 建立每日健康检查：磁盘、运行时、调度器、失败任务和输出积压。
2. 建立周度审计：权限变化、依赖变化、秘密轮换、异常外部写入。
3. 对配置、任务定义和文档做版本控制；对大文件和敏感数据采用独立备份策略。
4. 建立升级窗口、回滚方案和灾难恢复演练。
5. 为每项能力指定所有者、SLA、告警通道和停用流程。

完成标准：

- 节点可在重启后恢复到明确、可解释的状态。
- 任一自动化都能一键停用且不会丢失审计证据。
- 资产、权限、调度和运行结果都有统一视图。

## 4. 推荐的首个建设切片

建议下一阶段只建设一个最小闭环：

> Codex 调度 → 读取一份离线 IBKR 状态快照 → 生成脱敏中文状态报告 → 本地验收 → 输出审计记录。

选择它的原因：已有只读 Skill 和量化报告资产，业务价值明确，同时可以完全避开 TWS 连接、生产 API、飞书写入和交易执行。这个切片通过后，再复用同一骨架接 EnergyMo 周报和飞书只读数据。

## 6. 明确不在当前阶段执行的事项

- 不安装依赖或升级运行时。
- 不运行现有业务脚本或测试。
- 不连接 TWS、IB Gateway 或券商账户。
- 不提交纸面或真实订单。
- 不调用飞书、Money、EnergyMo 或其他生产 API。
- 不启动、恢复或迁移运行中的 OpenClaw。
- 不修改 launchd、Codex 自动化、cron 或系统配置。
- 不读取或复制任何秘密值。
